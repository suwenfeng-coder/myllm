# 代码质量规范（Sonar 扫描基线）

本文记录 SonarQube for IDE 扫描中已处理的问题类型。后续开发默认遵守这些规则，避免同类问题回流。

## 安全与配置

- 禁止新增明文密码、Token、AK/SK、数据库口令等敏感信息到代码库。
- 本次按当前开发约定，`scripts/secrets.local.sh` 中的明文密码问题暂不修复；除该已知例外外，新代码必须使用环境变量、本地忽略配置或密钥管理方案。

## Java 编码规范

- 循环计数器只能由 `for`/循环结构本身推进，不要在循环体内修改计数变量；复杂跳转应拆成明确的状态变量或辅助方法。
- 不要在同一个方法里塞入过多分支。方法认知复杂度接近 Sonar 阈值时，拆成：
  - 输入准备；
  - 调用外部依赖；
  - 结果校验；
  - 成功/失败落库；
  - 事件记录。
- `@Transactional` 不要依赖同类内部自调用生效；需要事务边界时，抽到独立 Spring Bean。
- 可为空的外部返回值必须显式校验。模型响应、工具执行结果、外部 API 返回对象不能直接解引用。
- 捕获异常后必须至少做一件事：记录、转换为领域异常、返回稳定错误信封，或重新抛出带上下文的异常。
- 避免无意义泛型通配和未使用 import；工具执行等泛型边界应通过小型 typed helper 收口。
- 字符类正则优先用简洁写法，例如能用 `\w` 时不要写 `[A-Za-z0-9_]`。
- 嵌套三元表达式要拆成局部变量或 helper 方法；可读性优先于“一行写完”。

## 测试规范

- 测试中不要直接使用系统当前时间。需要时间值时使用固定常量，或注入 `Clock`。
- `assertThrows` 的 lambda 中只保留触发异常的单个调用；测试数据构造、参数准备提前放到 lambda 外。
- 布尔断言使用 `assertTrue`/`assertFalse`，不要写 `assertEquals(true/false, ...)` 或 `assertTrue(!...)`。
- 行为修复优先补回归测试：先看到失败，再实现修复，再确认通过。

## HTML / JavaScript 规范

- 表单控件必须有可关联的 `<label for="...">` 和控件 `id`。
- 仅用于展示的标题不要使用 `<label>`，使用普通元素和 `.block-label` 等样式类。
- HTML escape 等字符串全量替换优先用 `replaceAll`，不要用一串正则 `replace(/.../g, ...)`。
- 避免嵌套模板字符串；动态 HTML 片段应拆到命名 helper，例如 `modelAnswerBlock()`、`itemErrorBlock()`。
- 避免用空对象再逐步填充的无类型写法；从 DOM inputs 生成对象时优先使用 `Object.fromEntries` 或明确的构造函数。
- `catch` 不能静默吞掉异常。前端至少要更新错误提示；后端至少要记录或转换为稳定错误。
- 条件分支尽量写正向条件，减少 `if (!condition) ... else ...` 这类不易读结构。

## 提交前检查

常规代码改动至少运行：

```bash
make test-fast
```

涉及文档链接、入口文档或规范时运行：

```bash
make verify
```

涉及 Sonar 扫描整改时，还要在 IntelliJ IDEA 的 SonarQube for IDE 中重新扫描，确认除已知暂缓项外无新增问题。
